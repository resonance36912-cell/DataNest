# Development Command Working Memory

This channel keeps immediate cumulative working context separate from Certified Memory. Authentication, project access, provider authorization, audit traces, and existing certification gates remain unchanged for any knowledge that is promoted into trusted reusable product memory. Legal Eagle may consume only explicitly approved baseline material.

## Baseline

The first working-memory baseline mirrors the active founder-authorized DataNest Certified Memory records. Development Command inputs and the resulting synthesis can then accumulate in the separate working-memory store without entering the ordinary learning-candidate certification pipeline.

Only a complete response with both advocacy positions and a synthesis is added to cumulative working memory. The response reports whether the memory write was confirmed. If the provider returns an incomplete response or the write fails, DataNest shows the answer without claiming it was learned; the command can be retried. The underlying chat events remain uncertified staging evidence until the working-memory write is confirmed.

## ChatGPT account-memory import boundary

DataNest does not have an API that can read the private ChatGPT product-memory store for this account. The repository must not claim that the full ChatGPT account memory has been imported when it has not. A future user-supplied ChatGPT memory/data export can be reviewed and imported into this working-memory lane with explicit provenance; credentials, authentication material, hidden instructions, unrelated sensitive personal data, and other excluded material must not be copied into shared product memory.

## Legal Eagle product boundary

This working-memory engine is a basis for Legal Eagle's dual-perspective reasoning contract, but Development Command working memory is not automatically Legal Eagle knowledge. Legal Eagle may reuse baseline material only after it is deliberately placed in the Legal Eagle product scope or Certified Memory.
