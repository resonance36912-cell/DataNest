[ ] UNKNOWN capability state is not execution permission.

[ ] Projects own knowledge; Jobs own work; checkpoints preserve continuity.

[ ] No passwords, MFA recovery codes, reusable browser cookies, PATs, service-role keys, or DB passwords in Git, screenshots, audit reports, or AI prompts.

[ ] Human/AI inputs intended for production knowledge or scoring must follow staging/review/certification paths; no silent self-approval.

[ ] Think Tank decisions and learning require independent confirmation/approval where the workflow requires it.

[ ] Approved reusable knowledge does not auto-score, auto-certify, or auto-mint Sparks.

[ ] Sparks remain internal utility only: no cash purchase/redemption, P2P/external transfer, secondary market, or ownership/royalty effect.

[ ] Governance voting remains one active project member, one vote; Sparks, reputation, contribution share, and capital do not weight formal votes.

[ ] Governance does not amend contracts, create legal ownership, create royalties, grant project roles, or create financial authority.

[ ] Dispute resolutions preserve the challenged source record and create append-only correction/clarification records.

[ ] Project invitation alone does not create access or a vote; membership must become active after matching-account authentication.

[ ] The normal UI must not reintroduce Capacity or Operations Capabilities as general-user surfaces unless explicitly governed for a specialist/admin context.

[ ] Current operating direction is free promotion/no billing; flag any live billing, checkout, stale paid CTA, or pricing path as a release inconsistency.

# 6. Accessibility and Interaction Quality

## 6.1 Accessibility

Audit purpose. Assess keyboard, semantic, visual, and assistive-technology usability.

[ ] Keyboard-only navigation through sign-in, sidebar, forms, tables, dialogs, dropdowns, and critical actions.

[ ] Visible focus states and logical tab order.

[ ] Form labels, error associations, required indicators, status messages, and accessible names for icon-only controls.

[ ] Color contrast and non-color status cues.

[ ] Heading hierarchy and landmark structure.

[ ] Table readability and responsive alternatives for wide data tables.

[ ] Zoom to 200% and browser text scaling without lost functionality.

[ ] Meaningful loading/error text rather than spinner-only or generic failure states.

[ ] Accessible wording for governance decisions, Sparks, scoring, and status badges.

Evidence to return: Accessibility finding list with WCAG-oriented evidence, severity, and remediation.
